# AES Benchmark Graphs

Generated by `graphs.py`. All benchmarks run on input sizes 1, 10, 30, 50, 75, and 100 MB.

---

## Set 1 — All Three Variants (AES-128 vs Rijndael vs AES-NI)

These four graphs plot all 7 implementations together on a shared axis. Because AES-128 operates at single-digit MB/s throughput while AES-NI reaches into the thousands, the Rijndael and AES-NI lines are compressed toward the top and their differences are hard to read. Use Set 2 for a clearer view of those two.

### `encryption_time_comparison.png`
Encryption wall-clock time (seconds) vs input size. AES-128 C and OCaml grow steeply and dominate the upper portion of the chart, while Rijndael and AES-NI remain nearly flat near the x-axis at this scale.

### `decryption_time_comparison.png`
Same as above for decryption. AES-128 decryption is significantly slower than encryption in both C and OCaml — the manual table-lookup decrypt path is considerably heavier than the encrypt path. This makes the AES-128 lines even more dominant here.

### `encryption_speed_comparison.png`
Encryption throughput (MB/s) vs input size. AES-128 C and OCaml sit at ~4–5 MB/s. Rijndael sits around 150 MB/s. AES-NI C and OCaml reach 800–1900 MB/s (with some variance). AES-NI OxCaml SIMD (partial) is visible but lower than the other AES-NI lines because only part of the pipeline uses SIMD intrinsics.

### `decryption_speed_comparison.png`
Decryption throughput (MB/s) vs input size. AES-128 decryption drops to under 1 MB/s, reinforcing how costly the manual inverse cipher is. The AES-NI lines remain high but show more variance than the encryption direction.

## Set 2 — Rijndael vs AES-NI

The same four metrics with AES-128 removed, allowing the y-axis to scale to the actual range of these two variants. The performance gap between Rijndael (~150 MB/s) and AES-NI (~1000–1900 MB/s) and the behaviour of the OxCaml SIMD partial implementation are now clearly visible.

### `encryption_time_rijndael_vs_aes-ni.png`
Encryption time without AES-128. Rijndael C and OCaml (opt) are close to each other — the optimised OCaml is competitive with C across all input sizes. AES-NI C and OCaml are an order of magnitude faster. AES-NI OxCaml SIMD (partial) sits between Rijndael and the full AES-NI lines, reflecting the overhead of the incomplete SIMD path.

### `decryption_time_rijndael_vs_aes-ni.png`
Decryption time without AES-128. Rijndael OCaml (opt) again tracks C closely and even edges ahead at some sizes. The AES-NI OxCaml SIMD (partial) line is notably closer to Rijndael than to the native AES-NI implementations, confirming that the partial SIMD coverage limits throughput.

### `encryption_speed_rijndael_vs_aes-ni.png`
Encryption throughput without AES-128. The most useful graph for comparing Rijndael and AES-NI directly. Rijndael OCaml (opt) matches or slightly beats Rijndael C, showing the OCaml optimisations were effective. AES-NI C leads overall but with some noise across input sizes.

### `decryption_speed_rijndael_vs_aes-ni.png`
Decryption throughput without AES-128. Broadly mirrors the encryption throughput graph. AES-NI C and OCaml remain well ahead of Rijndael. OxCaml SIMD (partial) throughput is relatively stable across sizes, suggesting the bottleneck is in the non-SIMD portions of the implementation rather than data volume.
